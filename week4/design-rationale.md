# 潮汐邮局 · 第四周设计过程

## 玩家任务

委托 TP-042 已接取，蓝色信封 ×1 已装袋。玩家根据当前位置、固定目的地、坐标、潮汐与浅滩，规划一条通往蓝潮岛北侧码头的安全航线，然后确认出航。

## V3 的问题与老师反馈

V3 委托已经指定目的地，但地图仍让玩家在蓝潮岛和雾礁之间选择目的岛。路线由系统用直线展示，失败恢复是重新选择蓝潮岛，玩家没有实际的空间规划输入。

老师建议加入坐标、方位、海上地标与航标，让玩家依据空间信息自行设定路线。

## 第四周判断

将地图任务从“选择目的地”改成“规划到固定目的地的航线”。

| 元素 | 在任务中的角色 |
| --- | --- |
| Blue Tide Island / 蓝潮岛 | 委托确定的固定目标 |
| Fog Reef / 雾礁 | 低潮航行约束，不可选择为目的地 |
| W1、W2 | 玩家输入；通过拖动或方向键调整 |
| Route Status | 系统反馈；验证整段航线是否穿越危险区域 |
| Confirm Route | 明确操作结果；确认后记录航线并提供出航入口 |

## 信息与视觉决策

海图约占界面宽度的 73%，右侧使用窄纸本航线记录。复用 V3 纸张、海玻璃色、圆润图标与邮务印章，不沿用旧页面的大顶栏和底栏。

第一层是当前位置、蓝潮岛目标、航线、路线状态与确认按钮；第二层是坐标、航向、航程和潮汐窗口；第三层是等深线、水深、灯塔、浮标、礁石与图例。水深与地标用于判断哪里可通行，海图不是背景装饰。

海图以原创分层 SVG 构成。复用 `01_back.png` 返回语义、`04_map.png` 海图识别及 `05_sail.png` 当前位置与确认出航语义；地理、航点与航线保持可编辑。航向和距离来自同一虚构坐标尺度，默认总航程四舍五入为 2.4 nm，不是硬编码读数。

## 判断 → 操作 → 反馈 → 恢复

安全航线使用海绿色实线和圆形航点。拖动 W1 使 W1—W2 穿越雾礁时，危险航段改为珊瑚色虚线，浅滩增加斜线，海图与记录出现警告三角、错误原因和北航道恢复提示；确认按钮被禁用。

玩家沿轻虚线提示自行调整航点，离开危险区域后立即恢复安全状态。提示不代替玩家完成规划。灯塔小岛、陆地、旧沉船礁与重叠航点也会阻止确认，并给出对应原因。

确认后显示“航线已确认”与明确出航入口；再次调整会撤销确认和已记录的航行计划。普通入口保留本标签页的路线草稿；`?state=valid`、`?state=blocked` 提供确定性截图状态。
